## 2. Самостоятельно принятые решения

1. **Состояние вычисляется, а не вводится руками.** Ручной статус «в норме» при прошедшем сроке — это ровно та проблема, которую мы решаем.
2. **Просрочка = нарушен срок заказа или контрольный срок стадии.** Ранний сигнал важнее точного совпадения с «каждым третьим»; на панели доля по сроку заказа показана отдельно.
3. **Финансовые признаки не меняют операционное состояние.** Иначе «под риском» раздувается вопросами качества данных.
4. **Первоначальный срок неизменен.** Перенос виден всегда, а нарушение для закрытых заказов считается от него.
5. **Streamlit + JSON** вместо БД: для одного демонстратора достаточно, ограничение названо.

## 4. План развития (этап 2, по приоритету)

1. Создание заказа и импорт CSV из текущих таблиц с проверкой обязательных полей, типов, дат, дубликатов ID и отрицательных сумм.
2. Многопользовательское хранение и вход по ролям, чтобы журнал стал доказательным.
3. Длительность стадий из журнала и отчёт «где теряется время» для проверки H1–H3 (нумерация v1.1).
4. Чек-листы гейтов (замер подписан, материалы в наличии, ОТК пройден) вместо одного поля «следующее действие».
5. Учёт рекламаций со ссылкой на исходный заказ и стоимость переделки.
6. Еженедельный снимок KPI для динамики: сейчас панель показывает только текущий момент.
