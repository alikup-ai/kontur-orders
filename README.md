# Контур заказов — MVP панели операционного управления заказами (v1.2)

Внутренний инструмент для собственника и руководителей фабрики кухонь на заказ. Отвечает на вопрос:
**какие заказы требуют вмешательства сегодня, почему и кто выполняет следующий шаг.**

> Все данные синтетические (24 заказа). Пороги — демонстрационные допущения, кроме утверждённого порога плановой маржинальности для дилеров (15 %). Гипотезы о причинах срывов **не проверены**: для этого нужна ретроспектива на реальных заказах ([docs/04_coo_review.md](docs/04_coo_review.md), §3).

> Инструмент работает только вместе с организационными мерами ORG-01…ORG-06 ([docs/01_design.md](docs/01_design.md), §5): владелец заказа назначен приказом, совещание проходит по списку вмешательства, параллельные таблицы заморожены.

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py          # откроется http://localhost:8501
python -m pytest -q           # 107 автотестов, ~45 с
```

Требуется Python 3.10+. Проверено на Python 3.14.3, Streamlit 1.66, Windows 11.
**После обновления кода перезапускайте сервер**: Streamlit перечитывает `app.py`, но не модули `kontur/*` (наблюдение QA, [docs/06_qa_report.md](docs/06_qa_report.md), §4).
Данные хранятся в `data/kontur_state.json` (создаётся при первом запуске). Файл старой схемы (v1.0) не затирается, а сохраняется как `kontur_state.broken.json`, и интерфейс показывает предупреждение. Демо-даты считаются от дня сброса, поэтому сценарии актуальны в день показа. Сброс: боковая панель → «Сброс демо-данных».

Пороги задаются в `kontur/domain.py` (`Settings`) или в разделе `settings` файла данных. Экрана настроек нет намеренно ([docs/01_design.md](docs/01_design.md), §8.3).

| # | Действие | Что показать |
|---|---|---|
| 1 | «Требуют вмешательства» | 11 из 19 активных заказов с признаками: просрочены → заблокированы → под риском → маржа ниже порога. У каждого заказа: что делать, **кто** (исполнитель), к какому сроку, последняя причина и подтверждена ли она |
| 2 | **KZ-26-104** в списке | Заказ в производстве, ответственный — мастер, но исполнитель действия — снабжение. Фильтр «Ответственный = Яковлева Т. (снабжение)» находит именно его |
| 3 | Карточка **KZ-26-102** | Два отклонения (прежнее не затёрто). Возврат стадии 4 → 3: «Дней по стадиям» суммирует оба посещения стадии 3 (13 + 12 = 25). Ошибка возникла на замере, обнаружена в производстве |
| 4 | Там же: перенести плановый срок без отклонения → «Сохранить» | Ошибка: перенос требует отклонения. Указать причину, стадию возникновения и описание → сохранено. Первоначальный срок не изменился, появился признак «Срок перенесён» |
| 5 | «Панель руководителя» | «Просрочено» 2 → 1 из 17 (знаменатель — только заказы с договором). У каждого показателя есть знаменатель и правило (значок «?») |
| 6 | Там же, «За период» | «Закрыто с нарушением срока» 1 из 3: KZ-26-122 исключён, потому что срок не сверен с договором. «Срывы с подтверждённой причиной» — по последнему отклонению |
| 7 | Карточка **KZ-26-102** → «Подтвердить» | Отклонение подтверждено на совещании, «срывы с подтверждённой причиной» растут |
| 8 | Плановая экономика | Порог дилера 15 %: KZ-26-121 (11,9 %) ниже порога, KZ-26-114 (19,5 %) — норма. Рекламации в маржу не входят |
| 9 | **KZ-26-123** (до договора) → «Договор и экономика» → «Подписан договор» | До договора срок не оценивается; с договора срок фиксируется как первоначальный |

## Ключевые ограничения

- Однопользовательский режим: один JSON-файл. Если заказ изменён в другой вкладке после открытия формы, сохранение отклоняется с предупреждением, без молчаливой потери данных.
- Нет авторизации: «кто вносит изменения» выбирается вручную и не проверяется.
- Нет импорта из таблиц и CRM; обычные заказы не создаются, только рекламации по существующим.
- Нет фактических затрат, контрольных сроков стадий, графиков и выгрузки — это этап 2.
- Сроки — в календарных днях, без учёта праздников.
- Маржинальный доход — не прибыль.
- Синтетические данные подтверждают только корректность расчётов, но не выводы о компании ([docs/05_traceability_audit.md](docs/05_traceability_audit.md), §6).
